# Data Dictionary

## Purpose

This document defines the data schema, column naming conventions, units, and data-quality expectations for all datasets used in the platform. Every data pipeline must conform to these schemas.

---

## Market Data: Daily OHLCV

**Source:** Yahoo Finance (primary), may be supplemented with other vendors.
**Frequency:** Daily (EOD).
**Storage:** `data/raw/yahoo/daily/{ticker}_daily.parquet`

### Schema

| Column | Type | Description | Units | Nullable |
|---|---|---|---|---|
| `date` | datetime64[ns] | Trading date (UTC) | ISO 8601 | No |
| `open` | float64 | Opening price | Quote currency | No |
| `high` | float64 | Highest price of the day | Quote currency | No |
| `low` | float64 | Lowest price of the day | Quote currency | No |
| `close` | float64 | Closing price (unadjusted) | Quote currency | No |
| `adj_close` | float64 | Adjusted closing price (splits, dividends) | Quote currency | Yes |
| `volume` | int64 | Trading volume | Shares/contracts | Yes |

### Validation Rules
- `open`, `high`, `low`, `close` must all be > 0.
- `high` ≥ `open`, `close`, `low`.
- `low` ≤ `open`, `close`, `high`.
- No duplicate dates.
- Dates must be monotonically increasing.
- Missing dates within the date range must be flagged (trading holidays are expected gaps).

## Derived Data: Daily Returns

**Source:** Computed from OHLCV data by `core/returns.py`.
**Storage:** `data/processed/{ticker}_daily_returns.parquet`

### Schema

| Column | Type | Description | Units |
|---|---|---|---|
| `date` | datetime64[ns] | Trading date | ISO 8601 |
| `simple_return` | float64 | `(close_t / close_{t-1}) - 1` | Fraction |
| `log_return` | float64 | `ln(close_t / close_{t-1})` | Log fraction |
| `excess_return` | float64 | Log return minus risk-free rate (when available) | Log fraction |

### Validation Rules
- Returns must be computed on adjusted close when available, unadjusted close otherwise.
- Gaps > 1 trading day must not produce spurious multi-day returns (NaN fill convention).
- `-1.0 ≤ simple_return < ∞` (no return below −100%).

## Conventions

- **Dates:** ISO 8601 format (`YYYY-MM-DD`). All dates are in UTC unless otherwise specified.
- **Currencies:** ISO 4217 three-letter codes.
- **Returns:** Log returns preferred for time-series aggregation. Simple returns used for cross-sectional aggregation.
- **Pips:** 1 pip = 0.0001 for most FX pairs; 0.01 for JPY pairs. Defined per instrument in `pip_value`.
- **NaN handling:** Missing values are represented as NaN. Computations must propagate NaN or use explicit fill strategies with documentation.
- **Rounding:** Prices stored at full precision. Metrics rounded for display only (4 decimal places).
